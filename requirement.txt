==================================================================
  1.  PROJECT OVERVIEW
==================================================================

  The Vehicle Rental System is a menu-driven console application
  that manages customers, vehicles, rentals, returns and business
  revenue.

  The program has two portals:

     [*] Customer Portal
           Register, log in, and view personal details and
           rental status.

     [*] Admin Portal
           Manage customers and vehicles, rent and return
           vehicles, view revenue, and save data.

  All data is stored in plain text files so that it persists
  between program runs.

==================================================================
  4.  DATA FILES
==================================================================

  These files are created automatically in the same folder as
  the program.

  ------------------------------------------------------------
  | File                     | Contents                      |
  ------------------------------------------------------------
  | RegisteredCustomers.txt  | Name, phone, email, username, |
  |                          | password, rental status,      |
  |                          | vehicle index, days, rent due |
  |                          |                               |
  | RegisteredVehicles.txt   | Vehicle ID, name,             |
  |                          | identification number,        |
  |                          | rented flag, daily rent       |
  |                          |                               |
  | Revenue.txt              | Total business revenue        |
  ------------------------------------------------------------

  Notes:
     - If a file does not exist at first start, the program
       begins with empty data.
     - Data is written when the admin chooses "Save/Exit"
       (Admin Menu, option 6). Customer self-registration
       also saves customer data immediately.
     - Do not edit these files by hand. The format is
       line-based and sensitive to changes.


==================================================================
  5.  FUNCTIONAL REQUIREMENTS
==================================================================

  5.1  General
  ------------------------------------------------------------
  FR1   Main menu with: Customer Portal, Admin Portal, Exit.

  5.2  Customer Portal
  ------------------------------------------------------------
  FR2   Customer registration (name, phone, email, password).
          - Email is used as the username.
          - Duplicate names and duplicate emails are rejected.
  FR3   Customer login using username and password.
  FR4   Customer dashboard showing username, name, phone,
        email and rental status. If a vehicle is rented, the
        vehicle details and amount owed are also shown.

  5.3  Admin Portal  (login details in Section 6)
  ------------------------------------------------------------
  FR5   Customer Management
          - List all customers
          - Register a customer
          - Search a customer by email

  FR6   Vehicle Management
          - List all vehicles
          - Register a vehicle (auto ID: VEH-1, VEH-2, ...)
          - View available vehicles
          - View rented vehicles
          - Search a vehicle by ID

  FR7   Rent Vehicle
          - Select customer by name and vehicle by ID
          - Enter number of days
          - Amount owed = daily rent x number of days

  FR8   Return Vehicle
          - Enter vehicle ID and confirm the return
          - Pay the exact amount owed
          - Vehicle and customer become free again

  FR9   Transaction Details
          - Displays total business revenue

  FR10  Save/Exit
          - Saves customers, vehicles and revenue to files

==================================================================
  7.  KNOWN LIMITATIONS AND FUTURE IMPROVEMENTS
==================================================================

  [1]  Security
         Passwords are stored in plain text.
         Suggestion: hash passwords before saving.

  [2]  Input Validation
         Typing a letter at a numeric menu prompt can cause
         an endless input loop.
         Suggestion: use cin.fail(), cin.clear(), cin.ignore().

  [3]  Menu Design
         Menus call each other recursively instead of using
         loops, so long sessions grow the call stack.
         Suggestion: use a main loop with a switch statement.

  [4]  Daily Rent Storage
         Daily rent is stored as a string and converted with
         stof(). A non-numeric rent will crash the program.
         Suggestion: store rent as a float and validate it.

  [5]  Saving Behaviour
         Customers registered by the admin are not saved until
         Save/Exit is chosen.

  [6]  Customer Abilities
         Customers cannot rent or return vehicles themselves.

  [7]  Fixed Capacity
         Arrays limit the system to 10 customers/vehicles.
         Suggestion: use structs/classes with std::vector.
